# Пять одинаковых задач: Claude Code, Codex и Lumen

Зачем: понять, где агент Lumen уступает Claude Code и Codex, на одних и тех же задачах, а не на ощущениях.
Задачи маленькие (5–30 минут каждая), на Python без внешних зависимостей. У каждой есть скрытая проверка: агент её не видит.

## Как запустить

```bash
tools/agent-bench/setup.sh ~/bench
```

Получится `~/bench/claude-code/…`, `~/bench/codex/…`, `~/bench/lumen/…`: в каждой папке пять задач, каждая — свой git-репозиторий.

Дальше в каждой папке задачи открыть инструмент и дать ему **одинаковый текст** — содержимое `TASK.md`. Условия одинаковые:

- модель — самая сильная из доступных в инструменте, «думать» — высоко;
- права — без вопросов о каждом шаге (Claude Code: `--permission-mode acceptEdits` или обход; Codex: auto; Lumen: режим «Обход»);
- на вопросы агента отвечать одной фразой «реши сам» и записывать, сколько раз пришлось.

После всех задач:

```bash
tools/agent-bench/check.sh ~/bench
```

Скрипт сам прогонит скрытые проверки во временной копии и покажет таблицу «ок / ПРОВАЛ». Провалы описаны в `<задача>.check.log` рядом с папкой.

## Задачи

| № | Задача | Что проверяет |
|---|---|---|
| 1 | `01-bug` — дата «19.10.2026» разбирается неправильно | Найти причину, а не залатать тест. Скрытая проверка ловит и вторую ошибку в том же файле (високосные годы 1900 и 2100), о которой в задаче сказано только «проверь похожие» |
| 2 | `02-rename` — переименовать `calc_total` в `order_total` | Аккуратная правка в пяти файлах, включая `import … as …`, README и тесты. Старое имя остаётся рабочим с `DeprecationWarning` |
| 3 | `03-explain` — «почему порт из окружения не применяется?» | Расследование без правок: найти опечатку `APP_PRT` (config.py, строка 6) и не тронуть ни одного файла. Ответ сверить с ключом в `03-explain.check.log` |
| 4 | `04-feature` — команды `done <id>` и `list --json` в утилите | Функция целиком: код, понятная ошибка с кодом выхода 1, README, тесты; старый тест нужно обновить под новый вывод |
| 5 | `05-spec` — `mdtable.py` по SPEC.md | Длинная самостоятельная работа по спецификации из восьми пунктов (кириллица, эмодзи, `\|`, рваные строки, командная строка) с собственными тестами |

## Что записывать руками

| | Claude Code | Codex | Lumen |
|---|---|---|---|
| Скрытые проверки (из `check.sh`), из 5 | | | |
| Вопросов к человеку за все задачи | | | |
| Раз пришлось вмешаться (поправить, подтолкнуть) | | | |
| Ложных «готово» (сказал, что сделано и проверено, а проверка провалена) | | | |
| Время на все задачи | | | |
| Расход (токены или доля лимита) | | | |
| Задача 3: верный ответ и файлы не тронуты | | | |

Главные числа — ложные «готово» и вмешательства: именно из-за них агенту нельзя доверить работу целиком.

## Эталон

В `tools/agent-bench/solutions/` — эталонные решения задач 1, 2, 4, 5: ими проверено, что заготовки проваливают скрытые проверки, а правильное решение их проходит. Агентам их не показывать: `setup.sh` кладёт в папки задач только заготовки.
